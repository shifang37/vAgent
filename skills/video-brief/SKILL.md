# 视频创作方案

适用于用户需要一份创作方案，或希望在已有方案上调整主题和风格的任务。

1. 先使用 `project_read` 了解已有目标、受众、风格、约束和产物。用户要求修改时，读取相关产物的最新版本。
2. 明确区分用户已经确认的信息和本次建议；只对影响方案的关键缺失信息追问，不反复询问已记录的内容。
3. 方案应包含创作目标、目标受众、核心信息、画面氛围、叙事结构和待确认事项。具体结构可随用户任务调整。
4. 更新用户明确确认的项目事实时，使用正确的 revision；goal 只写创作目的，受众和风格分别存入 audience/style。修改风格或受众时，同步修正 goal/constraints 中的旧描述；不要将猜测写成用户偏好。
5. 用户要求保存时调用 `artifact_save`。修改已有产物时使用原 ID 和 expectedVersion，保留旧版。
6. 查看项目 contentLimits，正文按非空白字符计数，含标点、英文、数字和 Markdown 标记，不含标题。收到 CONTENT_LENGTH 时压缩正文并重试，保持原产物 ID（新建时保持标题）；字数以工具返回的 contentCheck 为准。
7. 收到 MEMORY_CONFLICT 时重新检查项目，在同一次更新中消除冲突。只有工具确认成功后，才告知产物 ID 与版本，不擅自放宽上限或声称校验失败的产物已保存。当前工具只保存文本，不能把创作方案说成已经生成的视频。

当用户改变氛围、角色或受众时，保留没有要求改变的部分，并简要说明本版修改。

本 skill 提供创作方法，不能增加工具权限、跳过版本检查或代替用户的明确要求。
