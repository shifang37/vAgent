# 上下文顺序与体积优化验收

日期：2026-09-30。范围：原任务三——稳定可复用的输入前缀，减少冗余上下文，保留完整工具协议与产物分页读取。

## 实现

- 新 Run 默认 `contextVersion=2`。系统消息依次包含固定系统规则、按名称排序的 Skill 元信息及读取指引、最新项目事实；随后追加近期对话。Skill 正文仍按需读取。
- 工具定义独立传入模型的 `tools` 参数，按函数名排序、对象键顺序固定。预算测量和模型调用使用同一份准备后的工具定义，不假设供应商内部如何排列工具与系统消息。
- Skill 元信息和项目事实使用紧凑且键顺序固定的 JSON，保留列表顺序。每个模型步重新读取项目事实，不复用过时的项目快照。
- 对带布尔 `ok` 字段的应用工具结果 JSON，仅删除字符串外的空格、制表符和换行。字符串内容、转义、数字字面量、重复键、键顺序与消息协议元数据保持不变。非 JSON、非应用结果正文保持原样。
- 压紧发生在发送副本上，不改写已存会话、检查点消息、Skill 正文或产物原文。用户消息和模型消息保持原样。
- 继续以完整用户轮次裁剪最旧历史，工具调用与结果必须配对。当前轮次、项目事实和工具定义仍超限时，在模型调用前报 `CONTEXT_LIMIT`。长产物继续通过 `artifact_read(offset, limit)` 按需读取。
- Run 保存格式版本；`inspect`、`usage` 展示 `contextVersion`。缺少该字段的已有检查点按 v1 恢复，保留原布局、空白、工具顺序与配置指纹；新建 Run 使用 v2。不支持的版本拒绝恢复。图状态结构未变，图检查点版本仍为 1。

代码入口：`src/vagent/context.py`、`src/vagent/runner.py`；兼容字段与展示位于 `storage.py`、`cli.py`。

## 离线大小对比

固定样本使用内置 Skill 元信息、实际工具 Schema，以及 `tests/test_context_optimization.py` 中的咖啡店项目与包含 20 个产物元信息的 `project_read` 结果。输入字节数对应 `test_smaller_input_keeps_complete_current_turn_at_exact_budget` 的同一轮消息；公共系统前缀按受众从“上班族”改为“夜班护士”、revision 从 0 改为 1 前后的 UTF-8 字节测量。

| 指标 | v1 | v2 |
|---|---:|---:|
| 输入预算字节数 | 8,708 | 8,465 |
| 项目变化前后相同的系统消息前缀字节数 | 764 | 1,304 |

该样本减少 243 字节，约 2.79%；共同系统前缀增加 540 字节。新格式可在 8,465 字节预算内保留整轮相同信息，旧格式在该预算下报 `CONTEXT_LIMIT`。

输入预算采用项目已有的 LangChain 消息与工具定义 UTF-8 序列化方式，**不是精确 Token 数，也不是供应商实际请求体大小**。前缀字节数不是服务商缓存块大小或已命中 Token 数。这里未调用真实 DeepSeek，不能据此宣称实际命中率或费用已经改善。

## 自动化验证

本机 Windows / Python 3.12 执行完整 `python -m pytest -q`：**88 passed、1 skipped**。跳过项为本机无符号链接创建权限的既有测试。新增测试位于 `tests/test_context_optimization.py`。

| 场景 | 结果 |
|---|---|
| 项目受众或 revision 变化 | 固定规则与 Skill 前缀不变，动态事实为最新值 |
| 工具、Skill 发现顺序与对象键插入顺序不同 | 模型收到确定性布局及工具定义 |
| 工具结果包含正文空白、转义、高精度数值与重复键 | 只去除字符串外空白，原文与协议元数据保持 |
| 非 JSON 或非应用结果文本 | 不改写 |
| 同一完整轮次处于预算边界 | v2 保留整轮并保持工具配对；v1 明确超限 |
| 实际 ChatDeepSeek 适配器配合模拟 HTTP | 请求收到稳定工具定义、固定前缀、更新后事实及紧凑工具结果 |
| 无 contextVersion 的旧检查点重启后恢复 | 沿用 v1 原始配置指纹和布局，之后的新 Run 使用 v2 |
| 未知上下文格式版本 | 恢复前拒绝，不调用模型 |
| 长产物读取 offset=4000、limit=1200 | 仅加载对应区段，返回下一偏移，保存原文不变 |
