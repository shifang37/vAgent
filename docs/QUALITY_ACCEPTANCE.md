# 记忆一致性与正文长度校验

日期：2026-10-08。对应下一阶段任务 1，修复首轮真实编排暴露的项目事实冲突与正文超限。原始真实模型报告和产物保持不变，本次验证使用离线模型与临时数据，没有发起付费 API 请求。

## 行为

- `goal` 描述创作目的，`audience` 和 `style` 分别保存受众和风格。目标不重复这两个字段的原值。替换受众/风格时检查目标、约束是否仍引用旧值；历史操作日志中保留的项目快照用于识别已经发生的旧数据冲突。
- `project_read` 返回 `memoryConflicts`。`project_update` 和 `artifact_save` 在写入前校验；发生 `MEMORY_CONFLICT` 时保持项目 revision、现有产物与版本不变。模型通过同一次项目更新清理相关旧描述，保留未要求修改的事实。
- 计数对象是正文，不包含 title。口径为非空白 Unicode 码点数，标点、英文、数字、Markdown 标记均计入；空格、换行不计。组合字符和 emoji 序列按各自码点计数，不按视觉字形或模型 Token 计数。
- 用户的明确数字要求（如“brief 不超过300字”“分镜500字以内”）由后端解析为 `project.contentLimits`。支持方案/brief、脚本/script、分镜/storyboard，各产物分别校验；无种类的正文要求设置 `all` 默认上限。新上限随请求事务保存并更新 revision；重复 request ID 不重复写入，只读请求不修改。
- 上限跨会话轮次和重启保留。普通工具不能设置、放宽或删除这个字段。用户可明确说“brief 改为500字以内”或“brief 取消字数限制”；只取消一种产物时，其他产物保留原上限。
- 标题、纯聊天回复要求、围栏代码块、引用行和 Web 标记的附件参考材料不用于设定正文上限。当前不实现汉字专用计数、英文词数、字数区间，或任意自然语言约束解析；应使用上述明确数字形式。
- `artifact_save` 超限返回 `CONTENT_LENGTH` 与实际计数，不创建产物或版本。纯空白正文返回 `CONTENT_EMPTY`。成功时把 `contentCheck`（计数、上限、计数方法）写入版本并返回；旧版本不补造校验数据。
- 如果模型在收到这些校验错误后直接声称完成，Runner 返回 `QUALITY_UNRESOLVED` 并移除该条未获工具支持的最终回复。模型需针对同一产物重新保存（修改保留 ID，新建保留标题）；纠错仍使用原 Run 的步数、工具、时间预算。检查点恢复不会丢失未解决的错误。
- Web 的编排观测显示上限，产物面板显示保存时的计数与上限。固定任务评测从正文重新计数、检查项目事实，质量问题将使状态变为 `quality-failed` 并返回非零退出码，不再归为通过。
