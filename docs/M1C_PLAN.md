# M1-C 任务规划：真实单镜头视频与本地媒体交付

更新日期：2026-10-10。状态：**C0–C2 已完成，C3 尚未实施**。C0 交付 [官方接口核实](./VIDEO_API_NOTES.md)、[冻结契约与迁移夹具](./M1C_CONTRACTS.md)；C1 的版本兼容、万相协议、配置与工具见 [C1 验收](./M1C_C1_ACCEPTANCE.md)，媒体交付、恢复与浏览器验证见 [C2 验收](./M1C_C2_ACCEPTANCE.md)。依据：[M1 总计划](../M1_PLAN.md)、[当前能力](../README.md)、[M1-B 验收](./M1B_ACCEPTANCE.md) 和现有视频模块。沿用总计划的 C0–C3 编号，包内按依赖拆分实施。

### C0：核实什么

`VIDEO_API_NOTES.md` 为每项结论记录官方文档链接、查阅日期和证据状态，区分“文档支持”“当前账号已验证”“尚未确认”。至少包括：

| 核实项 | 需要确定的内容 |
|---|---|
| 模型与账户 | 精确模型 ID、地域、开通条件、工作空间与 Key 的匹配关系；一个可执行默认规格 |
| 输入与输出 | 提示词长度、时长/分辨率/画幅的合法组合、默认参数、音频/水印等影响输出或计费的选项、MP4 容器及浏览器所需编码 |
| HTTP 协议 | 服务端固定的提交/查询地址、鉴权头、异步任务标记、task ID 和 request ID、响应字段、状态转换、查询建议间隔与限流 |
| 提交歧义 | 哪些响应明确未受理，哪些网络/协议错误必须保留 unknown；是否存在可核实的服务端幂等或原请求查询能力 |
| 结果与生命周期 | 任务可查询期限、下载 URL 的有效期、合法 CDN/重定向目标、原 task ID 能否刷新 URL、是否支持取消 |
| 价格与费用 | 币种、计费单位、选定规格单价、失败计费规则、附加参数费用、可取得的实际账单字段；免费额度单独说明 |

C0 不通过生成视频来验证保存配置。没有可用的非生成验证接口时，只显示“已配置”，视频权限待真实联调验证。核实不支持的规格直接从能力表移除；不能默默改模型、换地域或降低用户规格。

## 4. C1 契约与兼容方案

下列为实现方向；字段细节、错误码、迁移夹具及兼容边界已由 C0 的 [M1C_CONTRACTS.md](./M1C_CONTRACTS.md)冻结，C1 据此实施。

1. **配置与身份**：新增 `videoMode=live`，首个真实 `provider=wan`。视频凭证沿用总计划的 `VAGENT_DASHSCOPE_KEY`；模型、地域、能力/价格版本由服务端配置。Key 与下载签名不进入工具结果、模型提示词、SSE 或公开配置接口。
2. **能力与请求**：保留现有四工具名称、服务端执行上下文、来源 ID/版本校验及每 Run 一个 Job 的去重规则。能力表与新建 Job 按原 Run 的模式筛选，避免恢复旧任务所装配的其他适配器被用于新提交。冻结完整请求、实际默认参数、模型/地域、能力版本和估价依据；模型不能提供认证信息、供应商地址或提交幂等键。
3. **两种结果**：上游成功给出私有 `ProviderOutput`，包含原任务身份、媒体位置和可取得的输出元数据；`JobResult` 表示最终本地交付。真实结果只有文件提交成功后才允许 `simulated=false`、`mediaAvailable=true`，并携带稳定的 `mediaRefs`。
4. **媒体模型**：schema v3 新增独立 `media` 索引。`MediaAsset` 保存 mediaId、projectId、jobId、来源文本版本、受控相对路径、MIME、大小、SHA-256、创建时间和已知规格。文本 Artifact 继续保持 brief/script/storyboard 的内容与版本语义；浏览器和模型通过 ID 引用媒体。
5. **迁移**：读取旧 schema v1/v2 并备份后迁移到 v3；旧 Mock Job 保留 contract v1 与原请求指纹，新真实 Job 使用 contract v2。保留旧 Run、Operation、来源版本、等待结果与 SQLite 检查点，不用重新计算指纹来绕过兼容校验。
6. **恢复视图**：旧 off/mock Run 保留其系统规则、工具 Schema、执行版本和上下文指纹。live 使用独立版本的能力视图；视频工具可见时继续跳过 Redis 回答缓存。恢复不增加原模型/工具/活动时间预算。
7. **费用**：估价由后端根据已核实的价格版本和完整规格计算并持久保存，使用 Decimal 或整数金额。记录币种、估算额、依据时间、实际费用的取得状态；未取得账单时标为未知，不能将估算或优惠额度当成实际扣费。真实提交受已配置的单 Job 金额上限约束，未知价格或超额时在提交前返回明确原因。

真实 HTTP 客户端与现有 DeepSeek 客户端分开管理。提交不做隐式重试；只有明确未受理才归类为提交失败，可能已受理的超时、响应丢失或缺失任务 ID 保留 unknown。查询只作用于原 task ID，按持久策略有限重试；未知上游状态作为协议异常处理，不能推断为成功或生成失败。

启动模式决定新 Run 的能力集合，旧 Job 按保存的供应商、地域和版本恢复。缺少旧任务的 Key 或适配器时保留任务与结果，向 CLI/Web 暴露需要补齐的配置，不替换成当前默认模型，也不连续空转请求。

## 5. C2 状态、下载和恢复

真实任务已实现以下状态；Mock 保持原路径：

```text
pending_submit → submitting → queued/running → downloading → succeeded
                      ↓             ↓               ↓
                   unknown        failed       download_failed
                                                    ↓
                                               downloading
```

上游可直接返回终态，因此 `submitting` 或 `queued` 也可进入 `downloading`；提交被明确拒绝时进入 `failed`。查询健康度仍独立表示 polling/retrying/paused，查询故障不改写已确认的生成状态。下载失败保存 `error.stage=download`，保留已成功生成的上游输出与 task ID。

- `await_job` 在真实 `downloading` 期间继续等待；本地交付成功后回填原 toolCallId。下载重试耗尽返回明确的 `JOB_DOWNLOAD_FAILED`，保留可修复 Job；后续下载成功更新 Job 卡片，不自动复活已结束或被停止的 Run，也不改写已交付工具结果。
- 沿用现有等待截止时间及活动/外部等待分开计时。若等待先超时，Job 和下载可以继续，用户随后查询或重新等待；等待与下载不能反复调用 DeepSeek。
- 增加独立、受应用管理的串行媒体 Worker，以异步流式 I/O 下载。下载期间不持有 Store 事务锁，不占用 JobWorker 的轮询步骤；退出时关闭响应和文件，保留恢复意图。
- 下载到数据目录下由服务端 ID 决定的位置，例如 `media/<projectId>/<mediaId>.mp4.part`。设置连接、读取、总时长和实际字节数上限；仅检查 Content-Length 不足以限制无长度或伪报长度的响应。
- C0 冻结的本地下载保护值为：256 MiB 上限、连接 10 秒、读取 30 秒、每次总时长 180 秒、一个并发下载。单次自动恢复窗口最多 3 次尝试；计数、下次执行时间与总次数持久化，重启不刷新额度。这些是本地资源策略，不是官方媒体大小/耗时保证。
- 短时连接或传输中断可在限额内重试下载；磁盘不足、权限错误、非法类型和超限停止并说明修复方式。首期从头下载新的 `.part`，不实现上游断点续传。浏览器播放的 Range 支持属于独立要求。
- C0 未取得延长临时 URL 或结果保留期的官方承诺，首期关闭结果 URL 刷新；过期后保留可操作错误，不通过重复查询或新生成修复。此路径的 submit 次数保持不变。
- 媒体来源限定为适配器返回的 HTTPS 地址，每次重定向复核目标域名/地址和跳转上限；下载客户端不携带视频 API 的鉴权头。文件写入只接受服务端媒体 ID，核验路径位于媒体目录内。签名 URL 不进入页面或模型上下文。

文件系统与 JSON 状态采用可恢复的提交顺序：

1. 持久登记下载意图、稳定 mediaId 和尝试次数。
2. 流式写入 `.part`，核对大小、MP4 结构及可取得的完整性信息，计算 SHA-256，刷盘并关闭文件。
3. 保存待提交文件的大小/哈希等恢复元数据，再在同一目录原子发布最终文件，保留已有冲突文件。
4. 在一次 Store 事务中提交 MediaAsset、真实 JobResult 和 Job succeeded，随后才允许等待结果交付。
5. 启动时核对 `.part`、最终文件及提交阶段；依据记录校验并完成原 mediaId 的提交，或重新下载。强退点不得产生重复媒体引用、未写完的成功文件或第二次生成。

后续读取发现本地文件缺失时，接口返回明确的媒体不可用状态，页面移除可播放入口；已交付的历史工具结果保持原样。需要重新取回媒体时仍复用原上游任务，不能自动生成替代视频。

### CLI/Web 交付

以下接口已在 C2 实现，证据见 [C2 验收](./M1C_C2_ACCEPTANCE.md)：

| 接口或入口 | 行为 |
|---|---|
| `GET /api/media/{mediaId}` | 返回当前媒体可用性、规格、大小和来源；不返回磁盘绝对路径或签名 URL |
| `GET/HEAD /api/media/{mediaId}/content` | 按 ID 读取本地 MP4；正确处理完整响应、单 Range 的 206、不可满足的 416 与相关长度头 |
| `POST /api/jobs/{jobId}/retry-download` | 请求体为 `{clientRequestId, expectedRevision}`，返回 202；重复请求/正在下载时不创建第二个执行，沿用 CSRF，参数冲突或旧 revision 返回 409 |
| `vagent jobs retry-download JOB_ID` | 与 Web 共用服务；Job 查询输出媒体 ID、受控本地位置、下载状态和费用记录 |
| 设置页 | 视频 Key、供应商/模型/地域、估价与金额上限；展示配置来源和需要重启的修改，保存配置不产生视频任务 |
| Job 卡片 | 区分模拟、云端排队/生成、下载中、已完成、查询暂停和下载失败；显示原来源版本、实际采用参数、估价/实际费用状态 |
| 本地播放器 | 仅完整媒体可用时显示；支持播放、拖动和下载，CSP 允许同源 media；刷新后恢复同一 Job/mediaId |

继续使用 Job revision 合并快照和 SSE，Run 结束后媒体状态仍可更新；快照更新保留同一播放器节点。读取会核验本地可用性并可能保存新 revision，不发起上游请求。下载流与页面渲染处理取消，保留 Python 3.11 的 CLI 退出回归。播放接口沿用本地 Host/Origin 边界，处理不存在 ID、路径越界、文件缺失和非法 Range；前端不展示虚构的生成进度百分比。

## 6. C3 验收矩阵

### 离线与故障验证

| 场景 | 必须核对的证据 |
|---|---|
| 真实协议 | 请求头/参数、原 task ID、立即完成和排队完成、明确拒绝、提交超时/断开、未知状态；重放与重复用户请求只有一次 submit |
| 配置与能力 | off/mock/live、缺 Key、无权限、非法规格与来源、费用上限、日志与响应脱敏；未提交时不创建收费请求 |
| 查询与结果 | 429/限流建议、短时故障、暂停/恢复、上游生成失败；只查询原任务，重复成功响应仅登记一个下载意图 |
| 媒体失败 | 流中断、无 Content-Length、超限、错误类型、截断文件、磁盘写入失败、URL 过期/刷新；下载重试不增加 submit |
| 文件提交强退 | 下载意图后、写入中、元数据保存后、重命名后、索引提交后、等待领取前后；复用原 Job/mediaId，只有完整文件可交付 |
| 状态竞争 | 生成完成与停止、下载完成与退出、重复恢复/重复下载按钮、等待先超时；旧 Run 不被意外唤醒，累计额度保持 |
| 数据与检查点 | v1/v2 → v3、旧 Mock Job、旧 off/mock Run 与已交付结果；原指纹、工具结果、源文本版本和实例锁保持 |
| 媒体接口与页面 | GET/HEAD/206/416、来源隔离、路径与重定向校验；播放器 loadedmetadata/播放/拖动、刷新、下载及失败恢复 |
| 既有能力 | M1-A/B 全量回归、只读/MCP/缓存、文本产物、SSE、CLI Ctrl+C、安装版启动与退出 |

下载和 Range 测试使用可控 HTTP 服务和有效的小型 MP4 夹具，验证实际字节与状态；费用估算、重试、迁移和崩溃补偿使用确定性场景。普通 CI 不从公共视频网站下载样本，也不依赖真实供应商。

### 真实联调与交付证据

- `scripts/evaluate_m1c.py` 默认离线；`--live` 显式启用真实文本与视频服务。评测必须保存套件身份、原 Run/Job、模型调用和视频提交预算，失败即停止；`--continue-from` 只续接可恢复的原任务，不能自动新建收费 Job。
- 首次真实验收默认最多 **1 个视频 Job、1 次 submit**。按 C0 的最终规格设置金额上限；模型每 Run 仍为 8 步、12 次工具、180 秒活动时间，套件额度与续跑累计保存。若要新增视频样本，需明确增加套件额度，不能用新 Run 或新报告绕过限制。
- 真实调用从仓库外安装的 wheel 发起，使用独立数据目录。一个成功样本依次核验自然语言工具调用、固定来源版本、原 task ID、完整文件、大小/哈希、浏览器实际元数据与播放下载；CLI/Web 复用这个结果，不为界面验收重复生成。
- 在可控等待或下载时点重启同一服务，核对原任务继续、submit=1、原 toolCallId 和预算。若云端完成太快导致某个真实恢复时点未覆盖，记录实际覆盖情况，保留离线强退证据，不能写成已做过的真实实验。
- 生成失败、查询限流、提交不确定、下载损坏等异常以离线注入验证为主。真实遇到的失败和未知费用如实保留；自动重试、手动恢复、URL 刷新和连接尝试分项记录。
- `M1C_ACCEPTANCE.md` 记录精确模型/地域/规格、模型与工具次数、submit/query/download 次数、生成/等待/下载耗时、Token 用量覆盖率、估价/已知账单、MP4 哈希与播放证据，以及无法验证的项目。
- 独立安装 smoke 覆盖文本、Mock 和真实协议夹具，包含媒体、配置、原 Job 恢复与退出清理。wheel/sdist 均可构建；最终提交通过 Ubuntu/Windows × Python 3.11/3.12 的四组 CI。测试数量根据实际新增结果记录，不预先填入通过数字。
