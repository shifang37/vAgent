# M2 任务规划：分镜多镜头工作流与素材库

更新日期：2026-10-16。状态：**D0、D1 已完成（D1 验收见 [M2_D1_ACCEPTANCE.md](./M2_D1_ACCEPTANCE.md)），D2 起进入实施**；M1-A/B/C 已全部验收完成，全部内容已合入 master（`cc3628e`，2026-10-16）。本文确定 M2 的范围、契约方向、工作包与验收要求；契约细节、新能力数值与上限提案在 D0 评审冻结后进入实施。工作包编号沿用零基惯例（M1-A→A0–A5、M1-B→B0–B5、M1-C→C0–C3），本阶段记为 **D0–D4**。

依据：[产品设计](../DESIGN.md) 的 M2 定义、[M1 总计划](../M1_PLAN.md) 的后续边界、[M1-C 冻结契约](./M1C_CONTRACTS.md)、[上游核实记录](./VIDEO_API_NOTES.md)、[M1-C 验收](./M1C_ACCEPTANCE.md)、[Harness 设计](../AGENT_HARNESS_DESIGN.md)。

阶段目标：用户一句话提出多镜头需求，Agent 结合创作方案形成**结构化分镜**（稳定镜头 ID 与版本）；用户确认后，应用为每个镜头登记一个真实视频 Job（受数量与金额上限约束），Worker 独立推进；逐镜头交付本地 MP4，可播放、下载，并可**只重做指定镜头**。素材库支持导入与复用参考图；用量统计聚合本地记录。图生视频、首尾帧与镜头延长在 D0 核实官方接口与价格后纳入能力表。

## 1. 进入条件与基线

- M1 于 2026-10-16 全部完成并合入 master（`cc3628e`）：M1-A 真实套件 9/9、M1-B 真实 DeepSeek + Mock 套件 5/5；M1-C 真实单镜头已交付本地 MP4（全程 submit=1，浏览器播放/拖动/下载通过）；全量回归 794 passed / 2 skipped；合并前的四组 CI 在最终提交 `cc3628e` 上全部通过。证据与限制见各验收文档，M1 历史证据以 [README](../README.md) 为准。
- 保留 M1-C 已冻结语义：单次提交、原 task ID 查询、完整媒体才 succeeded、来源允许集与下载策略、错误码与脱敏边界。M2 在其上扩展，不改写历史 Job/Run/媒体/检查点。
- 多镜头费用规则替换 M1-C 的“每个 Run 最多一个新视频 Job”：**一次生成调用可登记多个镜头 Job**，由“每 Job 金额、每 Run 新 Job 数、每 Run 累计估算金额”三重上限约束（提案数值见第 3 节，D0 冻结）。M1-C 的单镜头流程作为 N=1 特例继续可用。
- 新能力（图生视频、首尾帧、镜头延长）以 D0 官方核实为前提；未核实前能力表不出现对应条目，不实现未确认的模型 ID、规格或价格。
- 沿用既有边界：单数据目录单写进程、至多一个未结束 Agent Run（含等待）、真实调用只在显式 `--live` 或用户操作下发生、普通 CI 零费用。

## 2. 范围

### 2.1 本阶段实现

| 能力 | 内容 |
|---|---|
| 结构化分镜 | Storyboard/Shot 领域对象与版本；与脚本、创作方案产物的来源关系；稳定镜头 ID 支撑“重做第 3 个镜头” |
| 多镜头生成 | 批量登记（一次调用登记多个镜头 Job）、并发上限、逐镜头状态、部分失败隔离 |
| 逐镜头重做 | 显式用户发起；新 Shot 版本加一次新提交；仅影响目标镜头，其他镜头产物不动 |
| 图像输入模式 | 图生视频、首尾帧（以及镜头延长）按 D0 核实结果纳入；未核实模式明确不可用 |
| 素材库 | 本地导入/上传参考图，校验、去重、按 ID 引用与预览；不迁移、不重编码既有媒体 |
| 用量统计 | 读取侧聚合 Jobs、估算与账单状态、模型 Token 覆盖率；CLI 与 Web 面板 |
| CLI/Web | 分镜侧栏、镜头卡（播放、版本、重做）、批量确认、序列连播、素材库页、用量面板 |

### 2.2 明确不做（留待 M3 及以后）

- **拼接/转码成片**（M3 `assemble`）：M2 的“多镜头成片”交付形态为**逐镜头本地 MP4 加客户端序列连播**，最终单文件合成不算 M2 完成条件（决策点 1）。
- 参考音频、云端取消、多供应商与中转、按能力差异表自动选模型（仅实现逐模式能力报告与越界拒绝）、插件/skills 市场、Studio 可视化编辑器、素材删除与检索、headless、PyPI 发布、跨项目记忆。
- 旧文本 storyboard 产物**不自动转为结构化分镜**；结构化分镜可引用其版本作为来源。

## 3. 契约方向（D0 冻结）

### 3.1 数据对象（schema v4）

| 对象 | 要点（细节 D0 冻结） |
|---|---|
| `Storyboard` | id/projectId/title/sourceRefs（script、brief 等文本产物版本）/currentVersion/versions/revision/createdAt；版本语义与文本 Artifact 一致，修改保留原版 |
| `StoryboardVersion` | 有序 Shot 快照；版本只增不改 |
| `Shot`（快照内） | 服务端生成、跨版本稳定的 id；order/description/framing/cameraMovement（可选）/durationSeconds/mode/referenceAssetIds/extendSource 与参数快照 |
| `ShotVersion` | id/shotId/storyboardVersion/jobId/请求与估算快照/交付后 mediaId/createdAt；重做产生新版本，旧版本与媒体不动 |
| `Asset` | id/projectId/kind=image（预留 video）/relativePath（`assets/<projectId>/<assetId>.<ext>`）/mimeType/sizeBytes/sha256/dimensions/createdAt/source=user_import；生成视频仍在既有 `media` 索引，素材库在读取侧合并展示 |
| Job 扩展 | 新增只读链接 `shotRef{storyboardId,storyboardVersion,shotId,shotVersionId}`，创建时固定；不改变既有 Job 生命周期与状态机 |
| `CostRecord` 扩展 | 每次调用与每 Run 的逐镜头估算明细、上限与剩余额度快照 |

迁移：v3 → v4 **只新增 `storyboards`、`assets` 两个顶层集合**，历史对象不重编码、不补默认字段；沿用逐字节备份、失败保留原状态、未知版本拒绝打开的既有流程。固定 v3 基线夹具与 manifest 在 D0/D1 生成并提交。旧 Run 按原 tools/rules/execution/context 签名恢复；新 Run 使用 M2 工具与规则版本（提议 4/4）及能力版本 v2（命名 D0 冻结）。

### 3.2 生成模式与能力表 v2

- 保留 t2v 冻结条目（`wan2.7-t2v-2026-06-12`，北京，5 秒/720P/16:9，单任务估算 3.00 元）。
- D0 需核实并冻结各新模式的**精确模型版本、地域、规格组合、单价、提示词上限、输入图约束（格式/最小最大尺寸/大小/横竖比）、图片提供方式、结果与状态协议、限流**。
- **图片提供方式是首要风险**：确认本地上传的参考图如何送达上游（公网 URL、Base64/Data URL，或官方文件上传通道）。若上游仅接受公网可访问 URL 且无官方上传通道，对应模式明确裁剪并记录原因，不私搭公网暴露、不引入第三方图床。
- **延长输入形态**同样在 D0 确认（原任务 ID、视频 URL、媒体上传的哪种）；评估其与本地媒体缓存、24 小时链接窗口的关系，不满足时裁剪。
- `video_capabilities` 返回全部已核实条目；越界参数返回明确错误，不自动替换模型或规格。

### 3.3 费用与确认规则

- 三重上限（提案，数值 D0 冻结）：每 Job 估算上限 `videoMaxJobCost` = 3.00 CNY（既有）；每 Run 新真实 Job 数 `videoMaxNewJobsPerRun` = 4；每 Run 累计估算上限 `videoMaxRunCost` = 12.00 CNY（4 × 3.00）。批量调用的镜头数自然受剩余 Run 额度约束。设置页展示与下调；提交前校验剩余额度，超出整体拒绝并说明，不部分执行。
- 确认流程（提案，决策点 2）：沿用 M1-C 的“单阶段登记 + 强制估算回显”：生成工具结果固定包含逐镜头与合计估算、已用与剩余额度；服务端强制数量与金额上限；验收断言“回复包含合计估算，且提交数不超过用户确认的镜头集合”。
- 批量登记原子性：一次调用先校验全部镜头（来源、模式、上限、去重），任一失败整体不登记；通过后在同一次 Store 事务登记全部 Job。
- 重做与会话入口：重做仅由用户显式发起（对话、Web 重做按钮、`vagent shots redo`）；产生新 ShotVersion 与一个新 Job。去重按 ShotVersion 作用域：同一 ShotVersion 的重复登记复用原 Job；重做不受该复用限制（指纹与去重范围的精确定义在 D0 冻结）。失败与 unknown 沿用 M1-C：不自动重提、不自动换参数重试。
- 真实样本额度（提案，决策点 3）：首个真实多镜头验收为 **2 镜头加 1 次单镜头重做，submit ≤ 3、累计估算 ≤ 9.00 CNY**，须显式批准额度后执行；零费用预检沿用 C3.2 方式（DeepSeek `GET /models`、对不存在任务 ID 的一次查询）。i2v/首尾帧/延长的真实样本默认不包含（决策点 5）。

### 3.4 等待、预算与执行

- `await_job` 扩展为集合语义（工具 v4）：接受非空 `jobIds` 列表，登记一次等待；全部 Job 到达可交付终态（成功、失败、unknown、查询暂停、下载失败）或达到等待期限（沿用 600 秒）后，返回**逐镜头结果与失败摘要**；单元素列表等价 M1-C 行为。超时返回已完成部分并允许显式重等；已交付结果不被后续事件改写。
- 推荐对话流程：分镜草案 Run（读项目、保存分镜、展示估算后结束）与生成 Run（批量登记、集合等待、逐镜头汇总）分离，确认点天然位于两个 Run 之间，沿用 8 步/12 工具/180 秒预算；同 Run 内完成 N=4 的登记加等待加汇总也在预算内。
- 并发：登记串行；同时在途真实 Job ≤ min（4，上游“处理中任务”上限减余量）（上游文档值每模型 5 个处理中任务，D0 复核）；查询沿用 15 秒与持久退避，多 Job 独立推进，单 Job 阻塞不扩散。
- 停止、退出、强退与重启复用 B1–C2 持久机制；新增“等待集合部分交付后重启”“重做期间原 Job 与媒体不受影响”“停止不唤醒”用例。

### 3.5 素材库

- 导入：Web 上传（multipart、CSRF、大小与类型上限，提案 ≤20 MiB 与 PNG/JPEG/WebP，D0 按上游输入约束定稿）与 `vagent assets import PATH`；魔数校验、尺寸读取、SHA-256；同项目同哈希复用既有 assetId；文件路径由服务端 ID 构造，沿用媒体目录的符号链接与 reparse point 保护。
- 读取：素材元数据与内容接口复用媒体 HTTP 语义与同源边界；素材库页列表与预览。
- 引用：镜头以 assetId 引用参考图；允许复用同一数据目录内其他项目的素材（素材库目的所在），来源 artifact 仍限定当前项目；不存在或越界资产拒绝。工具只读列出素材，不开放任意文件系统路径，上传只经本地受信入口；最终规则 D0 冻结。
- M2 不提供素材删除，避免引用悬空（决策点 6）。

### 3.6 CLI/Web 与用量统计

- Web：分镜侧栏（顺序、状态、缩略图、版本数）、镜头卡（参数、来源版本、版本列表、播放、重做、下载）、批量生成确认对话框（逐镜头与合计估算）、**序列连播**（客户端按顺序播放各镜头 MP4，非服务端拼接）、素材库页、用量面板、按镜头分组的 Job 卡；revision/SSE 合并与播放器节点保留语义沿用 C2。
- CLI：`vagent storyboard show`（只读）、`vagent shots redo SHOT_ID`（幂等：clientRequestId 加 revision）、`vagent assets list|import`、`vagent usage --project`。
- 用量统计：读取侧聚合既有记录（Jobs 计数与状态、估算与 actualStatus、模型 Token 与覆盖率，按项目与按日）；不引入计费真相，**实际账单仍未知的保持 unknown**；不做外部调用。
- 工具命名与 Schema 在 D0 冻结（提议 `storyboard_read`、`storyboard_save`、`shot_generate`，并保留 `video_generate` 单镜头兼容路径；以契约为准）。

## 5. 验收矩阵

### 离线与故障（每项独立断言）

| 场景 | 必须核对的证据 |
|---|---|
| 分镜版本 | 修改产生新版本、旧版本保留；revision 冲突拒绝；来源越界与跨项目 artifact 拒绝；文本上限与提示词上限交互 |
| 批量与去重 | 一次调用登记 N Job 的原子性；失败整体不登记；工具重放与重复用户请求不重复登记；同 ShotVersion 复用 Job |
| 费用护栏 | 超上限整体拒绝；未确认不提交；估算回显；额度跨重启不刷新；零费用路径不产生 submit |
| 重做 | 仅目标镜头新增版本与 Job；其他镜头产物、版本、Job 全不动；并发重做幂等 |
| 集合等待 | 全终态交付、部分失败摘要、超时部分结果与重等、停止、重启、Job 先完成；等待不增加模型调用 |
| 部分失败 | 单镜头失败不影响其他镜头推进与交付；失败镜头可单独重做恢复 |
| 多模式协议 | i2v、首尾帧、延长的受控请求、错误与限流；图片输入校验（格式、尺寸、大小、来源） |
| 素材 | 导入校验、同哈希复用、路径逃逸拒绝、不存在资产拒绝、读取接口与 404/410 语义 |
| 用量 | 聚合正确、unknown 保持、无外部调用、并发读写一致 |
| 迁移与兼容 | v3 夹具到 v4、强退点、旧 Run/Job/媒体/播放器/只读/缓存回归、签名不变 |
| 界面 | 前端状态测试（分镜、镜头、确认、连播）；受控浏览器播放、重做、素材库流程、零页面错误 |

### 真实联调与交付（规则）

- 默认离线；`--live` 显式启用；额度、submit 上限与失败即停沿用 M1-C 评测规则；`--continue-from` 只续接原任务，不新建收费 Job。
- 从仓库外安装 wheel 发起，独立数据目录；零费用预检先行。
- 逐镜头核验：自然语言到分镜到逐镜头工具调用、原 task ID、完整 MP4、大小与哈希、浏览器播放与下载；重做只新增一次提交，**其他镜头不重新生成**。
- 重启或重开服务不重复提交任何已登记任务；费用估算与账单状态如实记录（unknown 保持 unknown）。
- 报告保留全部失败与偏差；失败样本不重跑掩盖；未做真实样本的模式明确标注“未做真实样本”。

## 6. 决策点（评审时确认）

1. **拼接归属**：建议按 DESIGN 归 M3；M2 交付逐镜头 MP4 与连播预览。若要求 M2 内输出单文件，需增加本地 FFmpeg 拼接工作包与依赖引入评审。
2. **确认流程形态**：建议单阶段登记加上限强制与估算回显（M1-C 先例）；备选两阶段（先计划后提交），在 D0 评审。
3. **真实样本预算**：建议 submit ≤ 3、估算 ≤ 9.00 CNY，显式批准后执行。
4. **默认上限数值**：建议每 Run 4 个新真实 Job、累计 12.00 CNY，可在设置中下调。
5. **新模式的真实样本**：建议 i2v、首尾帧、延长默认不做真实调用，D0 核实后另行批准。
