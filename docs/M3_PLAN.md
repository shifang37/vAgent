# M3 任务规划：本地拼接成片、更多供应商与 headless 完善

更新日期：2026-10-17。状态：**规划草案，待评审冻结**；M1、M2 已全部完成并合入 master（M1 `cc3628e` 于 2026-10-16、M2 `8776482` 于 2026-10-17）。本文确定 M3 的范围、契约方向、工作包与验收要求；契约细节、新能力核实与数值提案在 E0 评审冻结后进入实施。工作包编号沿用零基惯例（M1-A→A0–A5、M1-B→B0–B5、M1-C→C0–C3、M2→D0–D4），本阶段记为 **E0–E4**。

依据：[产品设计](../DESIGN.md) 的 M3 定义、[M2 任务规划](./M2_PLAN.md) 的后续边界、[M2 契约](./M2_CONTRACTS.md)、[M2 验收](./M2_ACCEPTANCE.md)、[上游核实记录](./VIDEO_API_NOTES.md)、[Harness 设计](../AGENT_HARNESS_DESIGN.md)。

阶段目标：把 M2 的「逐镜头本地 MP4 + 客户端序列连播」升级为**本地拼接的单一成片文件**；在既有 Job/等待/预算机制上接入更多真实供应商与聚合中转（用户自备 Key；万相已在 M1-C/M2 完成，本阶段的「更多供应商」指其之外的直连与中转）；把视频配置收敛为「**两 Key 直用**」（只输入编排模型 Key 与视频模型 Key；地域、业务空间与端点自动解析并在保存时零费用验证；高级覆盖默认隐藏）；提供 `vagent headless` 无 Web 全流程与用户 skills 扩展点。验收标准沿用 DESIGN：**完整创作工作台，可扩展新模型**。

## 1. 进入条件与基线

- M2 于 2026-10-17 全部完成并合入 master（`8776482`）：D4 离线端到端套件 7/7、安装态 wheel smoke PASS、受控浏览器 7/7、四组 CI 通过；真实双镜头加一次单镜头重做联调完成（submit=3、估算 9.00 CNY，三个真实 MP4 本地交付）。全量回归 943 passed / 2 skipped（本机）。证据见 [M2 验收](./M2_ACCEPTANCE.md)。
- 保留 M1-C/M2 已冻结语义：单次提交、原 task ID 查询、完整媒体才 succeeded、来源允许集与下载策略、错误码与脱敏、三重上限、批量原子登记、重做只影响目标镜头、集合等待与持久恢复。M3 在其上扩展，不改写历史 Job/Run/媒体/检查点与签名。
- 拼接为**纯本地操作**：不新增供应商调用、不改变 submit 计数；成片进入 `media` 索引，沿用 `mp4-avc-v1` 校验、媒体 HTTP 语义与播放器边界。
- 新供应商与中转以 E0 官方核实为前提；未核实前能力表不出现对应条目，不实现未确认的模型 ID、规格或价格。
- 视频配置的最小输入为两个 API Key（编排模型 + 视频模型）；地域、业务空间与端点自动解析并在保存时零费用探测验证；业务空间与专属域名保留为高级覆盖与历史恢复路径，不改写历史 Job。
- 实际账单仍未知：估算为冻结价格表推算，M3 沿用如实记录（`unknown` 保持 `unknown`）。
- 沿用既有边界：单数据目录单写进程、至多一个未结束 Agent Run（含等待）、真实调用只在显式 `--live` 或用户操作下发生、普通 CI 零费用。

## 2. 范围

### 2.1 本阶段实现

| 能力 | 内容 |
|---|---|
| 本地拼接成片 | 按分镜顺序拼接当前版本已交付镜头，产出单一 MP4 成片；成片有稳定 ID 与只增不改版本；重拼（含重做后）产生新版本，旧成片与媒体不动；可播放、可拖动、可下载；零供应商费用 |
| 更多供应商与中转 | 万相之外接入经核实的直连供应商与聚合中转（用户自备 Key）；能力表 v3 逐供应商、逐模式报告；价格表、每 Job/每 Run 上限与来源策略按供应商扩展；未配置 Key 的供应商明确不可用 |
| 两 Key 直用（免地域配置） | 设置页以「编排模型 Key + 视频供应商 Key」为最小输入，保存即可用；地域、业务空间与端点自动解析（万相 Key-only 默认北京共享域名，见 [VIDEO_API_NOTES](./VIDEO_API_NOTES.md) 第 10 节）；保存时零费用只读探测验证；视频模式/供应商/模型/业务空间/专属域名收进高级覆盖、默认隐藏；视频 Key 保存后无需重启即可用于新登记 |
| headless 全流程 | `vagent headless`：不依赖 Web 与浏览器完成分镜草案、显式预算授权、批量生成、集合等待与本地拼接交付；默认不提交付费任务 |
| 插件/skills 扩展点 | 用户 skills 目录（元信息发现、按需读取、版本记录沿用内置契约）；扩展点不执行任意可执行代码 |
| CLI/Web | `vagent film assemble\|show`、`vagent headless`；Web 成片面板（拼接按钮、成片播放/拖动/下载、版本列表）；设置页多供应商 Key；用量面板按供应商分组 |

- 按能力差异表**自动选模型**：M3 仍只做逐供应商/逐模式能力报告与越界拒绝，不自动替换模型或规格。
- 镜头延长（视频续写）：M2 的重新纳入条件（上游提供与专属域名一致且非「勿用于生产环境」的文件通道）未变化前不重新评估。

## 3. 契约方向（E0 冻结）

### 3.1 数据对象（schema v5 提案）

- 新增 `films` 顶层集合。`Film`：`id`、`projectId`、`storyboardId`、`storyboardVersion`（来源版本快照）、`shots[]`（有序，`shotId`+`shotVersionId`+`mediaId` 快照）、`currentVersion`、`versions[]`（只增不改）、`revision`、`createdAt`。
- `FilmVersion`：`version`、`outputMediaId`（成片进入 `media` 索引）、`assembly`（拼接方案与参数快照：所选方案与版本、输入媒体哈希列表）、`createdAt`。
- 工具与能力版本：新 Run 工具与规则版本提议 **5/5**；能力版本 v3（多供应商命名 E0 冻结，提案 `multi-provider-v3`）；`executionVersion`/`contextVersion`/等待绑定版本按实现评估，集合等待语义不变。
- 迁移 v4 → v5 **只新增 `films` 集合**，历史对象不重编码、不补默认字段；固定 v4 基线夹具与 manifest 在 E0/E1 生成并提交；旧 Run 按原签名恢复。
- 工具命名 E0 冻结（提案 `film_assemble`、`film_read`，与 `storyboard_read` 同风格）。

### 3.2 拼接方案与语义（决策点 1）

- 技术候选：**A** 依赖 `imageio-ffmpeg`（pip 安装即自足，随依赖提供二进制；需评审体积与许可证）；**B** 系统 FFmpeg 探测（零新增依赖；缺失时明确错误与安装指引；CI 与 wheel smoke 需安装步骤）；**C** 纯 Python 同规格无损拼接（零依赖；只覆盖编码参数一致的镜头，需评审实现风险与验证成本）。E0 评审后冻结其一（或主备组合）。
- 输入约束：只接受当前分镜版本内**全部镜头已交付**且编码参数一致（容器/编码/分辨率/帧率/音频）的媒体；缺镜头、失败镜头或参数不一致时整体拒绝并列出差异，不静默转码、不部分拼接。
- 幂等与版本：拼接操作幂等（同输入同参数重放返回原 `FilmVersion`）；重拼仅由用户显式发起（对话、Web 按钮、CLI），幂等键沿用 `clientRequestId + revision`（D3 客户端 Run 先例）；产出的新 `FilmVersion` 只增不改。
- 产物规格：MP4 成片必须通过 `mp4-avc-v1` 校验；大小与 SHA-256 记录在 `FilmVersion` 与媒体索引；成片与逐镜头媒体同在本地媒体目录，播放/下载沿用媒体接口语义。

### 3.3 供应商与中转（E0 核实）

- 核实对象（提案，按评审裁剪）：直连候选 Kling（快手）、Sora（OpenAI）、Veo（Google）、Seedance（火山引擎）；中转候选 fal、Replicate（用户自备中转 Key）。每项核实：地域与网络可达性、模型版本与规格、单价与计费口径、输入方式（参考图送达）、异步提交/查询协议、结果主机与下载、限流、错误码。
- 不可行项明确裁剪并记录原因；沿用边界：不私搭公网暴露、不引入第三方图床、不使用非生产通道。
- 费用护栏：每供应商独立价格表版本与每 Job 估算上限；每 Run 新 Job 数与累计金额上限扩展为按供应商计量（提案数值 E0 冻结）；估算回显、确认流程与批量原子性沿用。
- 来源策略：`sourcePolicyVersion` 按供应商扩展（每个供应商独立允许集与下载策略），不泛放行、不合并允许集。
- Key 管理（两 Key 直用）：设置页与 `.env` 以「编排模型 Key + 每视频供应商一个 Key」为最小输入；地域、业务空间与端点自动解析——万相仅有 Key 时默认北京共享域名（跨业务空间鉴权），提供业务空间时用专属域名；保存时执行零费用只读探测（不存在任务 ID 的查询）验证鉴权，结果区分「鉴权通过 / 视频权限未验证」；新端点形态与 `workspaceId` 可选性在 M3 契约冻结；高级覆盖字段默认隐藏；沿用脱敏边界（日志、API 与界面不返回 Key）。

### 3.4 headless 契约

- `vagent headless PROMPT`：与 Web 共用同一 ApplicationService/Runner/Store 与持久机制。默认路径走到分镜草案与估算回显后结束，**不提交付费任务**；显式预算授权（决策点 4）后在同次调用内完成生成、集合等待与本地拼接，输出成片路径与结构化结果摘要。
- 退出码与错误分类纳入契约（成功 / 校验拒绝 / 预算拒绝 / 上游失败 / 等待超时）；等待、恢复与额度语义复用既有机制，不新增第二套状态机。

### 3.5 扩展点契约

- 用户 skills 目录（位置 E0 冻结，提案 `VAGENT_HOME/skills/`）：沿用内置 skills 的元信息契约与版本记录；发现顺序与重名冲突规则明确；坏文件不导致启动失败，返回明确错误。
- M3 不加载可执行插件代码；供应商扩展只经代码内适配器与已核实能力表。

## 5. 验收矩阵

### 离线与故障（每项独立断言）

| 场景 | 必须核对的证据 |
|---|---|
| 拼接正确性 | 镜头顺序与分镜一致；成片时长等于镜头时长之和（允许封装误差）；浏览器连续播放无断裂；哈希与大小记录；`mp4-avc-v1` 校验通过 |
| 拼接边界 | 缺镜头/未交付/失败镜头明确拒绝并列出；异规格镜头拒绝并列出差异；空分镜拒绝 |
| 成片版本 | 重拼产生新版本、旧成片与媒体不动；重做后重拼只引用新 `shotVersionId`；同参数重放幂等 |
| 拼接故障 | 拼接过程停止/崩溃/重启后状态一致（不产生半个成片）；重复拼接不重复产文件 |
| 拼接零费用 | 全流程 submit 计数不变；无供应商请求（受控上游计数为 0） |
| 供应商 | 每供应商请求体逐字段受控；越界参数按模式拒绝；未配置 Key 明确不可用且不阻塞其他供应商；价格与上限快照正确 |
| 配置（两 Key 直用） | 仅填两个 Key 即可保存；无业务空间时端点自动解析为共享域名；保存探测为零费用只读（无任务创建、无提交）；视频 Key 保存后新登记无需重启即用；高级覆盖默认隐藏、可显式展开；Key 不入日志、API 响应与界面 |
| 中转 | 中转协议受控请求；中转结果主机按供应商来源策略处理；中转失败错误映射与不自动重试沿用 |
| 用量与费用 | 按供应商聚合正确、估算与价格版本、`unknown` 保持、无外部调用、并发读写一致 |
| headless | 默认路径不产生任何提交；显式授权路径 submit 数与上限一致；退出码分类；结构化输出字段稳定 |
| 扩展点 | 用户 skill 发现/排序/重名冲突；坏文件报错但不崩溃；不执行任意代码；版本记录只增不改 |
| 迁移与兼容 | v4 夹具到 v5；pre-M3 Run/Job/媒体/播放器/只读/缓存回归；签名不变 |
| 界面 | 前端状态测试（成片面板）；受控浏览器拼接、成片播放/拖动/下载、零页面错误 |

### 真实联调与交付（规则）

- 默认离线；`--live` 显式启用；额度、submit 上限与失败即停沿用 M1-C/M2 评测规则；`--continue-from` 只续接原任务，不新建收费 Job。
- 如需付费样本（决策点 3），首个样本以两 Key 直用（仅 Key、共享域名）配置运行，验证共享域名提交路径可用；失败则记录并回退专属域名（高级覆盖），不自动重试。
- 建议首组真实验收为**零新增费用**：用 M2 真实数据目录（已含真实分镜与三个已交付镜头）从仓库外安装 wheel 执行本地拼接，核验成片播放/拖动/下载与哈希；如需新增付费样本（含 i2v/flf2v 真实样本，M2 遗留）按决策点 3 批准执行。
- 重启或重开服务不重复提交任何已登记任务；估算与账单状态如实记录（`unknown` 保持 `unknown`）。
- 报告保留全部失败与偏差；失败样本不重跑掩盖；未做真实样本的供应商明确标注「未做真实样本」。

## 6. 决策点（评审时确认）

1. **拼接技术方案**：候选 A（`imageio-ffmpeg` 依赖，pip 自足）/ B（系统 FFmpeg 探测，零依赖但需外部安装）/ C（纯 Python 同规格无损拼接）。建议 E0 对三者做实现、体积与许可证评审后冻结其一；倾向优先 A 或 C，避免在 CI 与用户环境引入手工安装步骤。
