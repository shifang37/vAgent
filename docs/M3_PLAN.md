# M3 任务规划：本地拼接成片、更多供应商与 headless 完善

更新日期：2026-10-21。状态：**E0、E1、E2 已完成；E3–E4 待实施**；M1、M2 已全部完成并合入 master（M1 `cc3628e` 于 2026-10-16、M2 `8776482` 于 2026-10-17）。本文确定 M3 的范围、契约方向、工作包与验收要求；E0 的官方核实、选型、版本与预算见 [M3 契约](./M3_CONTRACTS.md) 和 [E0 验收](./M3_E0_ACCEPTANCE.md)，本次 submit=0。工作包编号沿用零基惯例（M1-A→A0–A5、M1-B→B0–B5、M1-C→C0–C3、M2→D0–D4），本阶段记为 **E0–E4**。

依据：[产品设计](../DESIGN.md) 的 M3 定义、[M2 任务规划](./M2_PLAN.md) 的后续边界、[M2 契约](./M2_CONTRACTS.md)、[M2 验收](./M2_ACCEPTANCE.md)、[上游核实记录](./VIDEO_API_NOTES.md)、[Harness 设计](../AGENT_HARNESS_DESIGN.md)。

阶段目标：把 M2 的「逐镜头本地 MP4 + 客户端序列连播」升级为**本地拼接的单一成片文件**；在既有 Job/等待/预算机制上接入更多真实供应商与聚合中转（用户自备 Key；万相已在 M1-C/M2 完成，本阶段的「更多供应商」指其之外的直连与中转）；沿用 K 轨已完成的「**两 Key 直用**」（编排模型 Key 与所选视频供应商 Key，高级覆盖默认隐藏），按 provider 区分保存与权限验证；提供 `vagent headless` 无 Web 全流程与用户 skills 扩展点。验收标准沿用 DESIGN：**完整创作工作台，可扩展新模型**。

## 1. 进入条件与基线

- M2 于 2026-10-17 全部完成并合入 master（`8776482`）：D4 离线端到端套件 7/7、安装态 wheel smoke PASS、受控浏览器 7/7、四组 CI 通过；真实双镜头加一次单镜头重做联调完成（submit=3、估算 9.00 CNY，三个真实 MP4 本地交付）。全量回归 943 passed / 2 skipped（本机）。证据见 [M2 验收](./M2_ACCEPTANCE.md)。
- 保留 M1-C/M2 已冻结语义：单次提交、原 task ID 查询、完整媒体才 succeeded、来源允许集与下载策略、错误码与脱敏、三重上限、批量原子登记、重做只影响目标镜头、集合等待与持久恢复。M3 在其上扩展，不改写历史 Job/Run/媒体/检查点与签名。
- 拼接为**纯本地操作**：不新增供应商调用、不改变 submit 计数；成片进入 `media` 的 FilmMedia 分支，沿用 `mp4-avc-v1` 结构校验、媒体 HTTP 语义与播放器边界，另以 `mp4-copy-signature-v1` 验证流复制兼容性。
- E0 已核实 Kling 新 API 直连与 fal standard t2v 中转；仅发布契约所列最小组合，不把文档支持称为账号已验证。
- 万相两 Key、端点解析、保存探测与高级覆盖已由 K0–K3 完成；新增 provider 不从 Key 形状猜测身份，无已核实免费接口时只保存并标注权限未验证，不强行探测。
- 实际账单仍未知：估算为冻结价格表推算，M3 沿用如实记录（`unknown` 保持 `unknown`）。
- 沿用既有边界：单数据目录单写进程、至多一个未结束 Agent Run（含等待）、真实调用只在显式 `--live` 或用户操作下发生、普通 CI 零费用。

## 2. 范围

### 2.1 本阶段实现

| 能力 | 内容 |
|---|---|
| 本地拼接成片 | 按分镜顺序拼接当前版本已交付镜头，产出单一 MP4 成片；成片有稳定 ID 与只增不改版本；重拼（含重做后）产生新版本，旧成片与媒体不动；可播放、可拖动、可下载；零供应商费用 |
| 更多供应商与中转 | 万相之外接入经核实的直连供应商与聚合中转（用户自备 Key）；能力表 v3 逐供应商、逐模式报告；价格表、每 Job/每 Run 上限与来源策略按供应商扩展；未配置 Key 的供应商明确不可用 |
| 两 Key 直用（免地域配置） | 设置页以「编排模型 Key + 所选视频供应商 Key」为最小输入；万相沿用已完成 K 轨的共享域名解析与零费用只读探测（见 [VIDEO_API_NOTES](./VIDEO_API_NOTES.md) 第 10 节）；Kling/fal 固定官方 profile，无已核实免费接口时标注「已保存，鉴权/模型权限未验证」；高级覆盖默认隐藏，Key 热更新用于新登记 |
| headless 全流程 | `vagent headless`：不依赖 Web 与浏览器完成分镜草案、显式预算授权、批量生成、集合等待与本地拼接交付；默认不提交付费任务 |
| 插件/skills 扩展点 | 用户 skills 目录（元信息发现、按需读取、版本记录沿用内置契约）；扩展点不执行任意可执行代码 |
| CLI/Web | `vagent film assemble\|show`、`vagent headless`；Web 成片面板（拼接按钮、成片播放/拖动/下载、版本列表）；设置页多供应商 Key；用量面板按供应商分组 |

### 2.2 明确不做（留待后续阶段）

- 云端拼接/转码服务、在线剪辑时间线、转场/字幕/配乐合成、成片导出参数定制（分辨率/码率）；M3 成片沿用镜头原始编码参数并只接受参数一致的镜头。
- 参考音频（`driving_audio`）、云端取消、跨项目记忆、素材删除与检索、Studio 可视化编辑器、插件市场与可执行插件加载、PyPI 发布；是否纳入由决策点 6 确认，默认继续顺延。
- 按能力差异表**自动选模型**：M3 仍只做逐供应商/逐模式能力报告与越界拒绝，不自动替换模型或规格。
- 镜头延长（视频续写）：M2 的重新纳入条件（上游提供与专属域名一致且非「勿用于生产环境」的文件通道）未变化前不重新评估。

## 3. 已冻结契约（2026-10-21）

完整字段、不变量、错误码与授权形态见 [M3_CONTRACTS.md](./M3_CONTRACTS.md)，以下为实施索引。

- **数据与迁移**：E1 schema v5 只新增 `films` 并更新外壳版本；历史 JSON 不补字段。Film 的每个版本固定分镜版本/revision、有序 shot/job/media/哈希和引擎指纹；`media` 新增独立 FilmMedia 分支，不伪造 generation Job。v4 合成基线及 manifest 已提交到 `tests/fixtures/m3/`，E1 再实现真实迁移与恢复检查。
- **拼接**：选择 A，固定 `imageio-ffmpeg==0.6.0` 包内 FFmpeg、concat + stream copy，无系统自动回退、无转码。`mp4-copy-signature-v1` 额外验证 codec config、轨道与时间线，不能只比较旧元数据。AAC 预卷/DTS 边界已有合成实验反例，E1 必须按样本计算。最新 ShotVersion 未交付整体拒绝；同指纹复用，来源/参数改变追加版本；完成文件校验后原子登记版本和媒体。
- **工具与签名**：E1 新 Run 为 tools/rules **5/5**（`film_assemble`、`film_read`），E2 为 **6/6**（通用供应商协议）；旧版注册表/签名保留。execution/context/checkpoint 保持 **3/2/1**。E2 能力汇总 `multi-provider-v3`，新通用 Job/Request **v6**，历史 1–5 不变。
- **provider 最小集合**：Kling Singapore 新 API，`kling-3.0-turbo` t2v、720p、16:9、5秒、原生音频；fal `fal-ai/kling-video/v3/standard/text-to-video`、16:9、5秒、显式静音。其他直连/中转、图生/首尾帧/声音控制顺延。逐 provider 的认证任务结果绑定 exact origin，公网地址校验和连接固定、禁重定向，Wan 静态允许集保持。
- **预算**：Wan 保持 3/12 CNY；Kling 0.560 USD + 4 VIDEO_UNIT/5秒，默认上限每 Job 0.60 USD 且4 units、每 Run 2.40 USD 且16 units；fal 0.420 USD/5秒，默认上限每 Job 0.50 USD、每 Run 2.00 USD。全 Run 新 Job 共享硬上限4，不换汇、不跨 provider 挪额度；批量原子确认、unknown 保守预留、实际账单 unknown 规则不变。
- **headless**：默认草案与估算、视频 submit=0（编排文本可能收费）；先产生计划，再用 `--plan RUN_ID --plan-fingerprint SHA --confirm` 及 `--max-cost PROVIDER:CURRENCY=AMOUNT` 授权固定集合，Kling 还需 unit 上限。JSON、退出码、resume 和原预算续接按契约 §7，不创建第二套状态机。
- **skills**：默认内置根再用户根 `VAGENT_HOME/skills/`，内置名优先、坏用户文件隔离；显式 `VAGENT_SKILLS_DIR` 保留全量替换语义；32项/16KiB限制、raw哈希版本、按需读取、恢复签名保留，不执行代码。

## 5. 验收矩阵

### 离线与故障（每项独立断言）

| 场景 | 必须核对的证据 |
|---|---|
| 拼接正确性 | 镜头顺序与分镜一致；成片时长符合契约的逐接缝时间线偏移上限；浏览器连续播放无断裂；哈希与大小记录；`mp4-avc-v1` 校验通过 |
| 拼接边界 | 缺镜头/未交付/失败镜头明确拒绝并列出；异规格镜头拒绝并列出差异；空分镜拒绝 |
| 成片版本 | 重拼产生新版本、旧成片与媒体不动；重做后重拼只引用新 `shotVersionId`；同参数重放幂等 |
| 拼接故障 | 拼接过程停止/崩溃/重启后状态一致（不产生半个成片）；重复拼接不重复产文件 |
| 拼接零费用 | 全流程 submit 计数不变；无供应商请求（受控上游计数为 0） |
| 供应商 | 每供应商请求体逐字段受控；越界参数按模式拒绝；未配置 Key 明确不可用且不阻塞其他供应商；价格与上限快照正确 |
| 配置（两 Key 直用） | 仅填两个 Key 即可保存；Wan 无业务空间时用共享域名、保存探测为零费用只读（无任务创建、无提交）；Kling/fal 未有免费鉴权接口时准确显示未验证；Key 热更新用于新登记，高级覆盖默认隐藏；Key 不入日志、API 响应与界面 |
| 中转 | 中转协议受控请求；中转结果主机按供应商来源策略处理；中转失败错误映射与不自动重试沿用 |
| 用量与费用 | 按供应商聚合正确、估算与价格版本、`unknown` 保持、无外部调用、并发读写一致 |
| headless | 默认路径不产生任何提交；两阶段计划指纹与分镜 revision 原子核对，变化拒绝；显式授权路径 submit 数与上限一致；退出码分类；结构化输出字段稳定 |
| 扩展点 | 用户 skill 发现/排序/重名冲突；坏文件报错但不崩溃；不执行任意代码；版本记录只增不改 |
| 迁移与兼容 | v4 夹具到 v5；pre-M3 Run/Job/媒体/播放器/只读/缓存回归；签名不变 |
| 界面 | 前端状态测试（成片面板）；受控浏览器拼接、成片播放/拖动/下载、零页面错误 |

### 真实联调与交付（规则）

- 默认离线；`--live` 显式启用；额度、submit 上限与失败即停沿用 M1-C/M2 评测规则；`--continue-from` 只续接原任务，不新建收费 Job。
- 万相两 Key 共享域真实提交已由 K3 验证，E0 不重复；E4 新 provider 的付费样本仍须独立显式授权，失败保留、不自动重提。
- 建议首组真实验收为**零新增费用**：用 M2 真实数据目录（已含真实分镜与三个已交付镜头）从仓库外安装 wheel 执行本地拼接，核验成片播放/拖动/下载与哈希；如需新增付费样本（含 i2v/flf2v 真实样本，M2 遗留）按决策点 3 批准执行。
- 重启或重开服务不重复提交任何已登记任务；估算与账单状态如实记录（`unknown` 保持 `unknown`）。
- 报告保留全部失败与偏差；失败样本不重跑掩盖；未做真实样本的供应商明确标注「未做真实样本」。
