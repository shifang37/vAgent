# 两 Key 直用小范围实施方案（K 轨）

更新日期：2026-10-17。状态：**规划草案，待评审冻结（K0）**。目标：用户打开前端界面后，只输入编排模型（DeepSeek）Key 与视频模型 Key 即可直接使用；不要求填写地域或业务空间。本方案为独立小轨道 **K0–K3**，可在 [M3 任务规划](./M3_PLAN.md) 全线之前单独冻结并实施；实施后 M3 E2 中「两 Key 直用配置与设置页」由本轨承接，E2 保留多供应商与中转部分。

依据：[M3 任务规划](./M3_PLAN.md) 决策点 7；[VIDEO_API_NOTES](./VIDEO_API_NOTES.md) 第 10 节（零费用预研：共享域名鉴权与任务读取已实测）；[M1-C 冻结契约](./M1C_CONTRACTS.md) 与 [M2 契约](./M2_CONTRACTS.md)（M2 及以前冻结语义全部保持有效）。

## 1. 现状与差距

- live 目前要求视频 Key **加**业务空间 ID（`check_live_configuration`，`video/jobs.py`），端点固定为业务空间专属域名 `https://{workspaceId}.cn-beijing.maas.aliyuncs.com`。
- 请求/Job 契约 V2/V3 冻结记录 `workspace_id` 与 `endpoint_profile=beijing-workspace-v1`；提交、查询与恢复都要求与当前配置的业务空间完全一致。
- 设置页展示六个视频字段（模式/供应商/模型/地域/业务空间 ID/金额上限），业务空间看似必填。
- 已实测（零费用，2026-10-17）：同一北京 Key 在共享域名 `dashscope.aliyuncs.com` 可完成鉴权与任务读取，且与专属域名读取同一任务库；未创建任务、未产生费用（[VIDEO_API_NOTES](./VIDEO_API_NOTES.md) 第 10 节；`output/m3-keys-only-probe.json`）。共享域名的**提交**路径未实测，由首个真实样本验证。

## 2. 方案

### 2.1 端点解析

- 未配置业务空间：live 使用共享域名 `https://dashscope.aliyuncs.com`，端点形态记为 `beijing-shared-v1`。
- 配置了业务空间：维持现状（专属域名、`beijing-workspace-v1`），供高级用户与既有任务使用。
- 地域仍固定 `cn-beijing`（Key 自带地域归属，不提供地域输入）；鉴权、路径、请求头与请求体不变，仅主机不同。

### 2.2 契约（K0 冻结提案）

| 维度 | 冻结规则 |
|---|---|
| 请求 / Job 版本 | 新增 `VideoRequestV4`（单镜头）与 `VideoRequestV5`（镜头）及 `JobV4`/`JobV5`（contractVersion=4/5），**仅用于共享域新任务**；V2/V3 逐字节不动 |
| V4/V5 形状 | 同 V2/V3，但无 `workspace_id`、`endpoint_profile="beijing-shared-v1"`；`adapter_version` 沿用 `wan-http-v1` / `wan-http-v2`（请求体协议不变） |
| 恢复与匹配 | V2/V3 语义不变（业务空间不匹配即明确拒绝）；V4/V5 的端点由记录形态唯一确定（共享域名），恢复只要求视频 Key 有效，不依赖业务空间配置 |
| 分派 | `parse_job` 扩展 `{4, 5}`；历史版本校验器与签名逐字节不变 |
| 结果主机 | 沿用 `wan-result-hosts-v2` 允许集；若样本出现新主机，按既有规则追加 v3，不改写 v2 |

### 2.3 配置与校验

- `videoWorkspaceId` 保持可选（配置层已可选）；live 校验去掉业务空间必填，错误文案随之更新。
- 金额三重上限与价格版本不变（价格口径由地域与模型决定，不随域名变化）。
- 地域不提供输入；Key 地域不符由上游 401 按既有错误映射提示。

### 2.4 前端设置页

- 默认表单：DeepSeek Key（+ 模型，默认已填）、视频 API Key、视频模式开关（真实视频 / 关闭）。
- 「高级（可选）」折叠：供应商、模型、地域（固定值展示）、业务空间 ID、金额上限；填写业务空间即切回专属域名。
- 保存视频 Key 时执行**零费用只读探测**（不存在任务 ID 的查询，与 C3.2/D4 预检同法）；状态区分「鉴权通过 / 视频权限未验证」；探测失败不阻塞保存、不产生任务与费用。
- 视频 Key 保存后即可用于新登记（免重启），实现见 K1/K2。

### 2.5 明确不做（本轨）

- 不做业务空间自动发现（暂未找到无副作用接口；M3 E0 继续核实，如有结论另行变更）。
- 不做多供应商与中转（M3 E2 范围）。
- 不改变专属域名地位与共享域名「不再获得新特性」的既有表态；key-only 仅作为默认引导路径。

## 5. 决策点（评审时确认）

1. **视频 Key 生效方式**：建议免重启（保存后新登记即可用）；备选维持现状（重启生效）。
2. **模式默认**：建议保存视频 Key 时若模式为 off 自动切到 live（输入 Key 即表明使用意图；mock/off 保留在高级区）；备选保持手动切换。
3. **专属域名保留**：建议保留（配置业务空间仍走专属域名，历史任务语义不变）；备选新任务统一走共享域名。
4. **真实样本**：建议 K3 以一次单镜头样本实测共享域提交路径（submit=1、估算 3.00 CNY，显式批准后执行）；备选并入 M3 E4 首个付费样本，K 轨保持 0 提交。
5. **UI 字段**：建议高级折叠保留全部字段（`.env` 覆盖不变）；备选彻底移除业务空间/地域配置项。
