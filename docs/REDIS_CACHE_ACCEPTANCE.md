# Redis 回答缓存验收

日期：2026-09-30。范围：原任务四——为可复用的只读模型回答增加可选 Redis 缓存。

## 行为与边界

- `run/chat --read-only` 从工具注册表中移除所有 `effect=write` 工具，后端同样拒绝调用；仅限制领域写入，会话和检查点照常保存。只读模式保存到 Run，CLI 恢复自动沿用；相同 request ID 不能切换模式。旧 Run 缺少字段按普通模式处理，普通模式的旧配置指纹保持兼容。
- `VAGENT_REDIS_URL` 未设置时关闭缓存；默认 TTL 3600 秒，可配置 1～604800 秒。连接 URL 从配置展示中移除，异常仅记录状态，不保存凭据或异常原文。
- 在模型步、上下文组装之后查缓存；只缓存不带工具调用的非空纯文本，跳过明确截断响应。命中仍完成 LangGraph 与会话记录。模型步数和调用明细只统计实际模型尝试，不回填缓存响应原有 Token。
- SHA-256 键覆盖实际完整消息（包括历史、工具结果及元数据）、工具 Schema、系统规则、Skill 版本、上下文格式/预算、模型适配器配置、数据目录、完整项目与所属产物快照。键不包含可读正文；值包含回答文本，不包含 Token、工具调用和供应商元数据。
- 缓存每次 I/O 最多 0.5 秒、单条最多 256 KiB；连接/读取失败回退模型，损坏条目当作未命中，写入失败不影响正常返回。取消和 Run 总预算继续有效。数据变更通过新键失效，旧键由 TTL 清理。
- `usage.answerCache` 与供应商 `cacheHitTokens/cacheMissTokens` 分开，记录实际缓存访问/写入状态。恢复可能重复一次缓存访问，但不会把命中记为模型调用。没有后台重试、语义缓存、分布式锁或并发请求合并。

## 验证

`tests/test_answer_cache.py` 覆盖：

- 相同完整输入命中，模型仅调用一次，后一次为零模型步/调用/Token；重新打开存储后命中记录保留，重复恢复终态不重复执行。
- 历史、项目修订、产物和模型配置变化均未命中；单独检查数据目录、项目身份、Schema、规则/Skill 指纹等键依赖。
- 只读请求即使收到写工具调用也不会创建产物；普通 Run 不访问缓存；未配置 Redis 时只读正常执行。
- 损坏 JSON、错误数据结构、非 UTF-8、空值回退，读取超时与写入失败不破坏模型结果；取消向上传递。
- 工具响应、空回复、截断响应不入缓存；恢复保留只读模式，模式冲突拒绝；配置范围校验和 CLI 凭据脱敏。
- **本机真实 Redis 8.6.3**：临时目录、随机回环端口、关闭落盘持久化，重建客户端后仍命中，TTL 到期后未命中，关闭服务后模型正常回退。测试结束停止其创建的进程，不访问现有 Redis 数据。没有 `redis-server` 的环境仅跳过此集成测试。

测试为了比较完全相同的输入，会在独立测试存储中还原会话历史；这是测试准备，不是生产行为。正常连续对话会增加历史，因此同一句问题再次输入通常无法命中；工具调用 ID 变化也会导致精确匹配失败。当前实现只验证正确性，未验证真实 DeepSeek 请求分布、缓存命中率或账单收益。

现有恢复、工具、上下文、用量和 DeepSeek 模拟 HTTP 回归一同执行。所有模型结果来自离线测试，未调用真实 DeepSeek。

本地结果：**109 passed，1 skipped**（Windows 符号链接权限）；Ruff 检查、格式检查、`pip check` 和 sdist/wheel 构建通过。wheel 安装到新建独立虚拟环境后，在仓库外成功运行 `demo`、`usage`、`run --help` 并导入已安装的缓存模块；配置不可达 Redis 时离线 demo 仍正常完成。Redis 缓存集成测试使用源码环境运行，未进行真实模型付费请求。
